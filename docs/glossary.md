# Glossary

| Term | Meaning |
| --- | --- |
| **Acceptance criteria** | Concrete examples or conditions that show a feature meets its requirements. |
| **AI (Artificial Intelligence)** | The field of building systems that perform tasks associated with intelligence. |
| **Coding agent** | An AI system that can work through several steps in a project, using tools such as reading files, editing code or running commands, within granted permissions. |
| **Context** | The information a model receives to produce a response. |
| **Context window** | The limit on how much information a model can process in one request. |
| **Deep learning** | Machine learning using neural networks with many layers. |
| **Generative AI** | AI that creates new content such as text, code, images or audio. |
| **Hallucination** | An output that is false or not supported by the available information, presented as if it were true. |
| **Inference** | Using a trained model to produce an output from an input. |
| **LLM (Large Language Model)** | A model trained to work with language, often used in chat assistants. |
| **Machine learning** | A way of building AI systems by learning patterns from data. |
| **Non-goal** | Something the feature deliberately does not include. |
| **Plan (technical plan)** | A description of how a feature will be built: affected code, tools, storage and risks. |
| **Prompt** | The request or information sent to a model. |
| **Specification (spec)** | A document describing what to build, its scope, rules and acceptance criteria. |
| **Spec Kit** | GitHub's open-source toolkit for a spec-driven workflow with AI coding tools. |
| **Token** | A unit of text a model processes. It is not always the same as a word. |
| **Training** | The process in which a model learns from data, before it is used. |
